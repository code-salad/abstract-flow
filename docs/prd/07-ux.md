# 7. UX summary

- **Surface: local web app** — a Bun + Elysia API (`server/`) that indexes the repo, plus a Next.js 16 web app (`web/`) rendering the flow canvas, both started with one command (`just dev`). Full control of the canvas, no editor-panel size constraints; editor deep-links (`vscode://`) from day one. A VS Code extension can wrap the same API later — the engine/UI split (see [08-architecture.md](08-architecture.md)) keeps that door open.
- **First-run flow:** `codeflow ./my-repo` → indexing progress (streamed job status) → entry-point list → click route → flow view.
- **Core loop:** scan flow → expand a call → drill or focus → peek code → jump to editor.
- **Single-user, local, no accounts in v1.** No auth, no billing, no hosted anything. The permalink (F16) encodes view state in the URL fragment — shareable with anyone who has the same repo checked out.
