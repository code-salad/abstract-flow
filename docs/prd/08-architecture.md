# 8. Technical approach

Built on the standard modern-fullstack stack (Bun + Elysia, Next.js 16, Drizzle, DBOS, Hey API, Biome, OTel), adapted for a local-first single-user tool.

## 8.1 Repo shape

```
abstract-flow/
  justfile          just setup / just dev / just ci
  server/           Bun + Elysia API — the analysis engine
  web/              Next.js 16 + React 19 — the flow canvas
```

## 8.2 Server — Functional Core, Imperative Shell

The zero-hallucination guarantee (principle 1) is enforced by architecture: **all graph construction is pure, deterministic, and unit-tested code in `core/`**; all I/O lives in `shell/`.

```
server/src/
  core/                        PURE — the correctness-critical logic, fully tested
    cfg.ts + cfg.test.ts         basic-block construction + branch-level collapsing over a normalized AST
    labels.ts + labels.test.ts   the F9 labeling chain (comment → dominant call → verbatim)
    resolve.ts + resolve.test.ts call-site → target(s); explicit CandidateSet for dynamic dispatch
    entrypoints.ts + …           framework route/CLI/export detection rules (pure, over index data)
    types.ts                     FlowGraph, Block, Edge, SourceAnchor, CandidateSet — the domain vocabulary
  shell/
    http/                      Elysia groups: projects.ts, flows.ts, entrypoints.ts, jobs.ts
    providers/                 I/O adapters that feed core:
      ts-compiler.ts             TypeScript compiler API — typed AST + symbol resolution
      tree-sitter.ts             fast pre-pass: file discovery, incremental parse
      (each normalizes into core types; core never imports compiler APIs)
    db/                        Drizzle client + schema (functions, cfg_cache, call_sites, files)
    workflows/                 DBOS indexing pipeline (see 8.3)
    lib/                       env.ts (zod-validated), watch.ts (fs watcher → incremental jobs)
  index.ts                     composition root
```

- Core imports nothing from shell. The TS compiler and tree-sitter are **providers behind function-shaped ports** — core operates on normalized AST/symbol data, which is what makes CFG and resolution logic exhaustively unit-testable (`bun test`, colocated `*.test.ts`). The "zero correctness bugs" bar ([09-metrics.md](09-metrics.md)) lives or dies here.
- When a provider hits an AST shape it can't normalize, it throws a typed `UnresolvedError` that renders as an explicit "unresolved" node (F11) — never a guess, recorded as an OTel span event.

## 8.3 Indexing pipeline — DBOS durable workflows

- Indexing a repo is a **DBOS workflow** on a concurrency-limited queue: discover files (tree-sitter pass) → per-file parse+index steps → call-resolution table build. Each step checkpoints; a crash mid-index on a 100k-LOC repo resumes instead of restarting (G5 depends on this).
- `POST /v1/projects` enqueues and returns a workflow id; **`GET /v1/jobs/:id` long-polls** for progress, which directly drives the first-run progress UI.
- Watch mode (F3): fs watcher enqueues per-file re-index jobs keyed by content hash — already-indexed hashes are no-ops.
- CFGs are computed lazily on first request per function and cached (F2); the cache row is keyed by file hash, so invalidation is free.

## 8.4 Storage

- **Drizzle ORM over `bun:sqlite`.** A local tool must not require a Postgres server (principle 3: no database to stand up) — the on-disk index is a single SQLite file per project, keyed by file hash for incremental updates. Drizzle keeps the schema portable to Postgres if a hosted team index ships later ([11-open-questions.md](11-open-questions.md), Q1).
- Consider SCIP index format compatibility for future multi-language expansion.

## 8.5 API & client

- Elysia routes under `/v1` with `@elysiajs/openapi`; Scalar docs at `/v1/docs`.
- Web client is **generated by Hey API** from the committed `server/openapi.json` (→ TanStack Query hooks). The graph types the canvas renders are the same TypeBox schemas the server validated — no hand-written client drift.
- **No CORS**: the Next app proxies `/api/*` → the local API origin; browser calls stay same-origin.

## 8.6 Web — flow canvas

- Next.js 16 App Router, React 19, Tailwind v4, shadcn/ui for chrome (entry-point list, breadcrumb, code peek panel).
- **Layout: custom layered layout** tuned for the spine-and-side-exit convention, implemented as pure functions rendering to SVG. Generic force/graphviz layouts do not produce readable flow semantics and are explicitly rejected. Layout is deterministic (same graph → same picture), which also makes F16 exports stable.
- Code peek uses read-only syntax-highlighted source served by the API (`GET /v1/source?file&lines`); "open in editor" is a `vscode://file/...` deep link.
- Expansion state, entry point, and repo ref serialize into the URL (F16 permalink); SVG export is a serialization of the already-SVG canvas.

## 8.7 Cross-cutting

- **No LLM anywhere in the pipeline** — the stack's AI SDK layer is deliberately not scaffolded (non-goal). The deterministic index could later ground an optional LLM layer ([10-risks.md](10-risks.md)) without touching core.
- **No auth, no billing, no MCP endpoint in v1** — local single-user. An MCP server exposing the deterministic index to coding agents is a compelling v2 (agents hallucinate call graphs too), noted in [11-open-questions.md](11-open-questions.md).
- **Observability**: OpenTelemetry traces on indexing workflows and API, exported to PostHog — **strictly opt-in and off by default** (developers point this at private source code; telemetry-by-default kills trust). Exporter degrades to a no-op when unset.
- **Quality gates**: Biome (with the no-`as` GritQL plugin — casts are exactly how a "verifiably correct" tool quietly becomes wrong), `tsc --noEmit`, `bun test`, wired via lefthook pre-commit/pre-push and CI (`just ci`). Correctness regressions in `core/` are the P0 class from [09-metrics.md](09-metrics.md), so `core/` test coverage is a merge gate.
- **Releases**: Release Please, conventional commits scoped `feat(server):` / `fix(web):`, independent app versions.
